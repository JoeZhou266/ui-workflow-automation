<objective>
Extend the existing `${param}` expansion engine to locator `value` strings so selectors can be parameterized at runtime (e.g. `{"by": "id", "value": "${company_code}"}` or `//div[@id='${company_code}']`). Unlike element values (anchored, full-value-only, Phase 4/17), locators use partial/embedded expansion via a NEW non-anchored regex.

Purpose: Real CSS/XPath selectors embed the parameter inside a larger string; the existing anchored path cannot expand them. This makes locators reusable across runs driven by workflow params.

Output: A `resolve_locator_params` function in `value_resolver.py`, locator resolution wired into `ActionFactory.run`, and unit coverage. Element-value behavior is untouched (D-03).
</objective>

<seam_decision>
The seam is research option (b): resolve `element.locator` UPSTREAM in `ActionFactory`, lowest blast radius (only `action_factory.py` + `value_resolver.py` change).

CRITICAL correction to the research's local-variable sketch: `ElementActions.execute` reads `element.locator` internally at ~9 branches and does NOT take a separate locator argument. Resolving into a local `resolved_locator` variable would only cover the `is_visible` probe — the actual action would still use the raw `element.locator`. Therefore the executor MUST build a resolved `ElementDefinition` copy (via `element.model_copy(update={"locator": resolved_locator})`) and pass THAT copy to `is_visible`, `_execute_with_retry`, and `execute`. When no tokens are present (or no params), reuse the original `element` unchanged (zero allocation).

DEFERRED (acceptable per CONTEXT.md): non-element locators (pre_wait/post_wait conditions, load_criteria, spinner_locator, overlay_locator) flow through WaitManager/PageReadiness without params and are NOT expanded. The executor must record this tradeoff in the SUMMARY, not attempt to cover it.
</seam_decision>
