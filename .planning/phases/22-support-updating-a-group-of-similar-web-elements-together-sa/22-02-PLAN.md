## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow JSON author -> framework | Authored `index_range`, `${index}` tokens, and `parameters` are untrusted input crossing into model validation, the loader, and the engine loop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Tampering | `${index}` substitution into locator.value / name (locator injection) | mitigate | `index_range` is `Optional[List[int]]` — Pydantic enforces integer-only members at model construction. The loop substitutes `str(i)` of an int, which is a pure decimal string with no quotes/brackets/operators; it cannot break out of an id, CSS, or XPath literal. `test_xpath_locator_with_index` (Plan 01) guards this. Making the field integer-only (Task 1) is what makes this mitigation real, not assumed. |
| T-22-02 | Denial of Service | unbounded `index_range` loop (e.g. `[0, 999999]`) | accept | No hard range cap added. CONTEXT.md leaves the cap to Claude's Discretion; the range is author-declared and static (not attacker-supplied at runtime in this single-author framework), and a runaway range fails visibly via slow execution rather than silent corruption. Documented accept; a future phase may add a `MAX_INDEX_RANGE` constant in `src/core/constants.py` if a real need appears. A WARNING log on a missing `${index}` token (Pitfall 4) catches the most common authoring mistake. |
| T-22-03 | Spoofing / Confusion | workflow param named `index` silently shadowing the loop variable | mitigate | Reserved-name guard in `json_loader` (Task 2) raises `WorkflowValidationError` at load in both `load` and `load_raw` — fail-loud before execution rather than silent shadow at runtime. |
| T-22-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this phase — RESEARCH.md "Package Legitimacy Audit: not applicable" (pure internal extension, pydantic 2.13.4 already installed). No install task, no legitimacy checkpoint required. |
